# Independent blind spot-check of company data, 2026-11-24

Scope: `data/companies/aziza.json`, `bop.json`, `paltel.json`, `insurer.json`, checked against the official PDFs whose URLs are listed in `data/sources/<name>.md`. Nothing in `data/companies/`, `src/` or `tests/` was changed.

## Method
1. **Selection (fixed seed, keys only).** For each file I listed every numeric line key (`{v, src}` leaves outside `disclosures`), sorted them in lexicographic order and indexed them from 0. Each file has N keys. I took 13 indices `3, 3+s, 3+2s, … (13 values)` with `s = floor(N/13)`:
   - aziza: N=74, s=5, indices 3,8,…,63
   - bop: N=36, s=2, indices 3,5,…,27
   - paltel: N=76, s=5, indices 3,8,…,63
   - insurer: N=46, s=3, indices 3,6,…,39

   I also checked the auditor opinion and the first KAM title, for 15 checks per company. Every sample meets the coverage rule (≥2 cash-flow lines and ≥2 comparative-year lines), with one exception: BOP is a bank and its file has no cash-flow block.
2. **Blind reading.** I downloaded each official PDF and read every sampled line directly from the PDF. For scanned or outlined pages I rendered them to images with the Windows PDF engine; where a numeric text layer existed I also cross-read it. I wrote down my value and page before opening any JSON value.
3. **Comparison.** Only after that did I print the file's values and `src.page`. A line counts as a mismatch if it differs beyond rounding to the published unit, uses the wrong sign under `data/EXTRACTION-GUIDE.md`, or cites the wrong page.

**Blinding caveat.** I had to read the sources `.md` files to get the URLs, and they quote some figures, for example BOP gross loans and the Aziza capex components. So the auditor was not fully blind to those numbers. Every value below was still read from the PDF itself.
